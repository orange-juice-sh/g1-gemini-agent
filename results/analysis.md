# 本番評価の結果と失敗の分析（2026-10-18）

数値はすべて `results/final/SOURCES.txt` に並べた評価フォルダの `runs.csv` から、
`python plot_results.py $(cat results/final/SOURCES.txt) --out results/final` で再現できる。
後に並べたフォルダに同じ（モデル, タスク）の結果があれば、前の結果を置き換えて集計する。

## 条件

- 評価時のコード：commit 7e4e4eb（T11 の修正を含む）。その後に加えた変更（pick_up が自分で見回して探す、
  locate_point が部屋の外の点を失敗にする、ライブモード・Web UI の自動回避など）は、この評価には含まれない

- 環境：家具のあるロビー（Poly Haven・ambientCG の CC0 素材）、腕付き G1（g1_29dof_lock_waist）
- タスク：20 種類（基本8・難しい7・腕5、`g1_agent/tasks.py`）。成功はシミュレーションの最終状態とログから機械的に判定
- 試行回数：Argon 3回、ER 2・Flash 2回（費用の制約）、Qwen 3回、ルールベース 1回（決定的なため）
- 1試行の上限：AI への問い合わせ 30 回
- **T11 のやり直し**：初回の本番評価では、環境の作り込みで移したサイドテーブルの下に黄色い箱が隠れていた（タスクの不具合）。
  箱を見える位置に移し、T11 だけ全モデルでやり直して置き換えた（eval-20261018-1723xx〜1732xx）

## 読み取れること

1. **Gemini の3モデルはどれも 90% 以上で、信頼区間は重なっている。** この試行回数では、3モデルの間に統計的にはっきりした差はない。
   難しいタスク（視覚・文字・変化・長い手順・腕）でも、3モデルとも大半を解けた。
2. **最新のフラッグシップ推論モデル（Argon）が最良とは限らなかった。** ロボット向けの ER 2 が全問正解で、応答は Argon の約 1/4（4.8 秒 対 17.6 秒）、
   成功1回あたりの費用は約 6 割だった。今回のように「道具（スキル）がそろっていて、各手順は短い判断の連続」というエージェントでは、
   長い推論よりも、速さと空間・画像の理解のほうが効く場面が多かったと考えられる。
3. **Argon の強み**は、見回しの手数が少なく（平均ツール呼び出し 7.5 回）、報告が具体的で、demo の5場面を毎回1回目で成功したこと。
   弱みは応答の遅さで、実機では「考えている間に止まっている」時間が長くなる。
4. **ローカルの Qwen3-VL**は、基本のタスクはほぼ解けるが、再計画（同じ横歩きを左右に繰り返す）と画像での見分けが弱い。
   応答は 0.7 秒と圧倒的に速く、API 費用もかからない。
5. **ルールベース**は、決まった場所への移動と色の物の探索だけ解ける。曖昧な指示・文字・状況の変化・腕のタスクは解けない。

## 失敗の分類

| 種類 | 内容 | 該当 |
|---|---|---|
| 範囲の解釈 | 「休憩スペースの床の箱」に、少し離れた場所の青い箱まで数えて 4 個と答えた | Argon T11 2回、Flash T11 1回 |
| 探索の打ち切り | 聞いていた場所に忘れ物がないとき、探す範囲を広げきれずに問い合わせの上限に達した | Argon T13 1回、Flash T13 2回、Qwen T13 2回 |
| 紛らわしい物の取り違え | 同じ緑色の観葉植物を「緑のボール」と判断した | Flash T15 1回、Qwen T15 3回 |
| 再計画の空回り | 安全停止のたびに 0.8〜1m の横歩きを左右交互に繰り返し、避ける距離や経路を変えない | Qwen T3・T12（3回）・T13・T20 |
| 人の見分け | オレンジの服の来客を見つけられず、受付の人に話しかけた | Qwen T9 3回 |
| 数え間違い | 視野に入った箱だけ数える（0〜1個と答える） | Qwen T11 3回 |
| ツールの使い忘れ | `pick_up` を呼ばずに `put_down` を繰り返した | Qwen T20 1回 |
| 状況の誤認 | 安全停止で受付に着いていないのに、その場で指差して終えた | Qwen T19 1回 |

## 評価の限界（レポートに書くこと）

- 試行回数が少ない（1モデル 40〜60 試行）。信頼区間が広く、Gemini 3モデルの順位は入れ替わりうる
- タスクは自作で、シミュレーションの中だけ。家具の配置を変えたことで、タスクの不具合（T11）が1つ紛れ込んでいた
- 物をつかむ動作は簡略化（指先が届いたら固定）。腰を曲げられないので床の物は扱えない
- 費用はトークン数と公式の単価（キャッシュの割引込み）からの計算値。実際の請求額は AI Studio で確認する
